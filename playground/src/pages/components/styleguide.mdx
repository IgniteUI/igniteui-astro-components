# Style Guide

A reference page showing every HTML element related to text and typography,
rendered through the documentation theme.

## Headings

Six levels of section headings. Each level has a specific semantic role — choose based on document structure, not visual size.

| Element | Use when |
|---|---|
| `<h1>` | The single top-level title of the page. One per page. |
| `<h2>` | Major sections directly beneath the page title. |
| `<h3>` | Sub-sections within an `<h2>` section. |
| `<h4>` | Sub-sections within an `<h3>`, for deeper nesting. |
| `<h5>` | Rarely needed — deep nesting usually signals restructuring. |
| `<h6>` | Deepest level; use only when six distinct levels are genuinely required. |

<h1>Heading level 1 — page title, one per page</h1>
<h2>Heading level 2 — major section</h2>
<h3>Heading level 3 — sub-section</h3>
<h4>Heading level 4 — deeper sub-section</h4>
<h5>Heading level 5 — avoid unless strictly necessary</h5>
<h6>Heading level 6 — deepest level</h6>

```html
<h1>Heading level 1 — page title, one per page</h1>
<h2>Heading level 2 — major section</h2>
<h3>Heading level 3 — sub-section</h3>
<h4>Heading level 4 — deeper sub-section</h4>
<h5>Heading level 5 — avoid unless strictly necessary</h5>
<h6>Heading level 6 — deepest level</h6>
```

### Typography utility classes

When you need the *visual style* of a heading level on a different element —
for example, making an `<h2>` look like an `<h5>` without breaking the document
outline — use the `.igd-h1` – `.igd-h6` and `.igd-p` utility classes instead of
choosing the wrong semantic element.

| Class | Applies the visual style of |
|---|---|
| `.igd-h1` | `<h1>` |
| `.igd-h2` | `<h2>` |
| `.igd-h3` | `<h3>` |
| `.igd-h4` | `<h4>` |
| `.igd-h5` | `<h5>` |
| `.igd-h6` | `<h6>` |
| `.igd-p` | `<p>` (body text) |

```html
<!-- Semantically an h2, styled like an h5 -->
<h2 class="igd-h5">Section title that should appear smaller</h2>

<!-- A div that needs paragraph styling -->
<div class="igd-p">This text looks like a paragraph.</div>
```

example:
<h2 class="igd-h5">An h2 styled with `.igd-h5`</h2>
<h3 class="igd-h2">An h3 styled with `.igd-h2`</h3>

## Body text

The `<p>` element represents a paragraph of text. It is the
most common block-level element for prose content. Paragraphs are separated by
vertical margin and their line-height affects readability significantly.

A second paragraph follows immediately. Notice the consistent spacing between
paragraphs applied by the documentation theme. Long lines should wrap naturally
at the container boundary without any explicit `word-break` override
unless the content contains very long unbreakable strings.

```html
<p>A paragraph of body text — the most common block-level element for prose.</p>
<p>A second paragraph, separated from the first by vertical margin.</p>
```

## Tables

**Markdown** tables are automatically wrapped in an accessible scroll container
(`.igd-table-wrapper`) by the `rehypeTableWrapper` plugin. The wrapper gives the
table a border, a sticky header row, and a sticky first column, and it scrolls
independently once the content grows past `--igd-table-max-height`.

Raw **HTML** `<table>` elements are **not** auto-wrapped — add the
`.igd-table-wrapper` yourself, as the expandable example below does. A table
nested inside an already-wrapped table needs no extra wrapper; it shares the
same container and is styled like any other table.

### Standard table

A plain Markdown table. The header row pins to the top while scrolling
vertically, and the first column pins to the left while scrolling horizontally.

| Property | Type | Default | Reflects | Description |
|---|---|---|---|---|
| `value` | `string` | `""` | no | Current value of the input field. |
| `name` | `string` | `""` | yes | Name of the control, submitted with the form. |
| `label` | `string` | `""` | no | Text label rendered above the input. |
| `placeholder` | `string` | `""` | no | Placeholder shown while the field is empty. |
| `disabled` | `boolean` | `false` | yes | Disables the control and skips it on submit. |
| `required` | `boolean` | `false` | yes | Marks the field as required for validation. |
| `readonly` | `boolean` | `false` | yes | Makes the field non-editable but still focusable. |
| `outlined` | `boolean` | `false` | yes | Renders the outlined visual variant. |
| `size` | `"small" \| "medium" \| "large"` | `"medium"` | yes | Controls the density of the component. |
| `invalid` | `boolean` | `false` | yes | Reflects the current validation state. |

The Markdown source for the table above — Markdown tables are wrapped
automatically, so no extra markup is needed:

```md
| Property | Type | Default | Reflects | Description |
|---|---|---|---|---|
| `value` | `string` | `""` | no | Current value of the input field. |
| `disabled` | `boolean` | `false` | yes | Disables the control and skips it on submit. |
```

table. Each record is a pair of rows — a **summary** row with a chevron toggle
in its first cell, immediately followed by a hidden **detail** row. The toggle
is a visually hidden but keyboard-operable checkbox, so a row opens on click or
with <kbd>Space</kbd> while focused. It is **CSS-only** (a `:has()` selector) —
no JavaScript required.

## Code & preformatted

| Element | Example | Use when |
|---|---|---|
| `<code>` | Use `console.log()` for debugging | Inline code snippets, file names, values |
| `<kbd>` | Press <kbd>Ctrl</kbd>+<kbd>K</kbd> to open search | Keyboard input or shortcuts |
| `<samp>` | Output: <samp>Error: connection refused on port 3000</samp> | Program or terminal output |
| `<var>` | The formula uses variable <var>x</var> as input | Mathematical or programming variables |
| `<pre>` + `<code>` | See fenced block below | Multi-line preformatted code |
| `<pre>` alone | See block below | Preformatted text without code semantics |

```ts
// <pre> + <code> — preformatted code block
function greet(name: string): string {
  return `Hello, ${name}!`;
}

console.log(greet('World')); // Hello, World!
```

<pre>Plain preformatted text without code semantics.
  Leading whitespace    is    preserved.
    Indentation is respected.
— &lt;pre&gt; alone</pre>

<p>Use <code>console.log()</code> for debugging.</p>

## Images

### Basic image — `<img>`

The `<img>` element embeds a raster or vector image. Always include
a descriptive `alt` attribute for accessibility.

<img
  src="https://picsum.photos/seed/igniteui/800/400"
  alt="A random placeholder landscape photo"
  width="800"
  height="400"
/>

```html
<img
  src="/path/to/image.jpg"
  alt="A descriptive alternative text"
  width="800"
  height="400"
/>
```
